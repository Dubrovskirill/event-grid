# План разработки Event Grid

Этот документ — рабочая последовательность разработки. Он нужен для выбора
следующей задачи и фиксации прогресса. Детальные решения и полные требования
остаются в [технической спецификации](technical_specifications.md).

Статусы этапов:

- `[ ]` — не начат;
- `[-]` — в работе;
- `[x]` — завершён и проверен.

## Цель первого MVP

Пользователь может создать локальную прямоугольную карту, отметить ячейку,
открыть её редактор долгим нажатием, добавить заметку и теги, а затем
панорамировать и масштабировать карту. Данные сохраняются между запусками.

В MVP не входят: бесконечная сетка, игровые регионы, синхронизация, облако,
semantic zoom и сложная аналитика.

## Правила движения по плану

1. Одновременно выполнять один этап и одну небольшую пользовательскую задачу.
2. Перед архитектурным или функциональным изменением сверяться с
   `architecture.md`, `technical_specifications.md` и этим планом; при
   противоречии сначала согласовать документацию и решение.
3. Новый слой добавлять только тогда, когда он решает текущую задачу.
4. Каждое изменение доменных правил сопровождать тестом.
5. Производительность измерять, а не предполагать.
6. После завершения этапа обновлять его статус, кратко записывать результат в
   commit и переходить к следующему критерию готовности.
